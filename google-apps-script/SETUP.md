# 산학협력 문의·방문 신청 연결

현재 상태: Google 인증, 비공개 접수 스프레드시트 연결, Apps Script 웹 앱 배포를 완료했습니다. 2026년 10월 4일 테스트 문의의 시트 저장과 담당자 받은편지함의 알림 메일 수신을 확인했습니다. 아래 연결 절차는 다른 계정에서 다시 설치하거나 설정을 변경할 때 참고합니다.

2026년 10월 11일 버전 3에 방문회의·방문교육 신청을 추가했습니다. 기존 웹 앱 주소와 시트를 유지했으며, 실제 테스트 신청의 방문 정보 저장과 상세 내용이 포함된 알림 메일 수신을 확인했습니다.

## 동작 구조

홈페이지 하단의 문의 입력 → Google Apps Script에서 검증 → 비공개 Google 스프레드시트에 새 행 저장 → 지정한 담당자 이메일로 문의 내용과 시트 링크 발송.

실제 접수 화면은 Apps Script의 HTML을 홈페이지 안에 표시합니다. 저장 결과를 `google.script.run`으로 직접 확인하므로, 통신을 시도했다는 이유만으로 접수 성공을 표시하지 않습니다. 방문자는 Google 스프레드시트에 접근할 필요가 없습니다. 브라우저에서 삽입 화면이 준비되지 않으면 새 창으로 문의 양식을 여는 버튼이 표시됩니다.

## 한 번만 연결할 항목

1. 접수 목록을 소유할 Google 계정으로 [Google Apps Script](https://script.google.com/home)에 로그인하고 새 프로젝트를 만듭니다.
2. `Code.gs`를 프로젝트의 `Code.gs`에, `Index.html`을 HTML 파일 `Index`에 넣습니다. `Index.html`은 사이트의 `contact-form.html`과 같은 파일입니다.
3. 프로젝트 설정에서 매니페스트 표시를 켜고 제공한 `appsscript.json`을 적용합니다. 시간대는 서울이며, 시트 접근과 메일 보내기 권한만 사용합니다. Gmail 받은편지함 읽기 권한은 사용하지 않습니다.
4. 프로젝트 설정 → 스크립트 속성에 `NOTIFY_EMAIL`을 추가하고 알림받을 이메일 주소 한 개를 입력합니다. 이 값은 공개 HTML이나 GitHub에 넣지 않습니다.
5. 이미 만들어 둔 접수 목록의 ID를 `SPREADSHEET_ID`에 지정한 뒤 `setupInquiry`를 한 번 실행합니다. 처음에는 Google의 권한 허용 절차가 표시됩니다. 실행 로그에 접수 목록 링크가 나타납니다. 같은 설정으로 다시 실행해도 새 시트를 중복 생성하지 않습니다. 시트 ID를 생략하면 새 접수 목록을 만들므로, 이번에 생성된 목록을 쓰려면 ID를 먼저 지정합니다.
6. 배포 → 새 배포 → 웹 앱을 선택합니다. 실행 주체는 소유자, 접근 권한은 `모든 사용자`로 설정합니다. 응답 시트의 공유 권한을 공개로 바꾸지 않습니다. 조직 계정 정책으로 비로그인 웹 앱 접근이 제한되면 해당 계정에서는 이 배포 방식이 작동하지 않을 수 있습니다.
7. 생성된 `/exec` URL을 루트 `contact-config.js`의 `webAppUrl`과 `index.html`의 `inquiry-frame` 주소에 넣습니다. 끝이 `/dev`인 테스트 URL은 사용하지 않습니다.
8. 홈페이지를 새로 열어 실제 테스트 문의 한 건을 제출합니다. 화면의 접수번호, 시트의 새 행, 담당자 수신함의 알림 메일을 확인한 후 공개 접수를 시작합니다. 이번 연결에서는 실제 서버 저장과 메일 수신까지 검증했습니다.

Google Apps Script 코드를 변경한 뒤에는 배포 관리에서 새 버전으로 업데이트해야 합니다. 기존 배포를 업데이트하면 홈페이지에 넣은 URL을 유지할 수 있습니다.

## 접수 목록과 운영

기본 수집 항목은 회사·기관명, 담당자 이름, 회신 이메일, 전화번호, 문의·신청 유형, 문의·신청 내용, 추가 요청사항, 개인정보 이용 동의입니다. 접수시각과 접수번호는 자동 기록됩니다.

방문회의·방문교육·방문 세미나는 희망 일정, 희망 장소, 참석 대상·예상 인원을 선택적으로 입력합니다. 방문교육에만 희망 교육 시간이 추가됩니다. 신청 유형에서 방문 항목을 해제하면 숨겨진 방문 정보는 저장하지 않습니다. 방문 일정은 접수 후 담당자와 협의합니다.

열 배치: A:F 접수일시·접수번호·회사·기관명·담당자 이름·회신 이메일·전화번호, G:I 문의·신청 유형·문의·신청 내용·추가 요청사항, J:M 개인정보 이용 동의·검토 상태·담당자 메모·알림 메일 상태, N:Q 희망 일정·희망 장소·참석 대상·예상 인원·희망 교육 시간. 기존 검토 상태와 메모 열의 위치를 바꾸지 않습니다.

`검토 상태` 열은 신규 / 검토 중 / 연락 완료 / 협의 중 / 종료 중에서 선택하고, `담당자 메모`에 후속 내용을 남길 수 있습니다. 운영팀의 시트 공유는 실제 담당자가 정해진 뒤 필요한 계정에만 설정합니다. 연락처와 원문은 공개 사이트에 노출하지 않습니다.

메일에는 문의·신청 내용 전체와 접수 목록 링크가 들어갑니다. 방문 신청은 제목에 신청 유형이 표시되고, 본문에 방문 상세 정보가 포함됩니다. 메일의 답장 주소는 신청자 주소입니다. 신청자에게 자동 회신 메일을 보내지는 않습니다.

## 기존 13열 양식에서 업데이트

1. 기존 접수 행과 A:M 열의 위치를 유지합니다. N:Q가 비어 있는지 확인한 뒤 첫 행에 `희망 일정`, `희망 장소`, `참석 대상·예상 인원`, `희망 교육 시간`을 추가합니다.
2. Apps Script의 `Code.gs`와 `Index.html`을 함께 교체하고 저장합니다. 배포 관리에서 기존 배포를 새 버전으로 업데이트하여 `/exec` 주소를 유지합니다. 기존 권한 범위와 비공개 시트 설정도 유지합니다.
3. G:I의 제목을 `문의·신청 유형`, `문의·신청 내용`, `추가 요청사항`으로 변경합니다. 새 서버는 업데이트 중 이전 제목도 허용합니다.
4. 방문교육 테스트 신청의 접수번호, N:Q 값, M열 메일 발송 상태를 확인합니다. 이전에 열어 둔 양식에서 새 방문 필드를 보내지 않아도 기존 문의는 접수됩니다.

이 업데이트는 기존 시트를 재생성하거나 `setupInquiry`를 다시 실행할 필요가 없습니다.

메일 발송이 실패해도 시트에 저장된 문의는 유지됩니다. `알림 메일 상태` 열에 실패가 표시되므로 운영 중에는 시트도 확인합니다. Google Apps Script의 계정별 발송 할당량과 웹 앱 접근 정책은 계정에 따라 달라질 수 있습니다.

## 구현된 검증

- 필수 항목, 이메일·전화번호 형식, 입력 길이, 문의·신청 유형, 동의 여부를 화면과 서버에서 확인합니다. 방문 상세 정보는 선택 사항이며 서버에서도 길이와 형식을 확인합니다.
- 같은 접수번호의 재전송은 중복 행을 만들지 않습니다. 통신 지연 때도 입력 내용을 유지합니다.
- 스프레드시트에서 수식으로 해석될 수 있는 사용자 입력을 일반 텍스트로 저장합니다.
- 숨김 항목과 너무 빠른 제출을 확인하고, 동일 이메일의 짧은 시간 내 반복 접수를 제한합니다. 대량 스팸 방어를 보장하는 CAPTCHA 서비스는 아닙니다.
- 미연결 상태의 버튼은 `입력 내용 확인`이며, 저장·메일 발송이 없다는 안내를 표시합니다.
- 문의자의 연락처나 내용을 브라우저 저장소에 보관하지 않습니다.
